UI redesign · v2

One list,
three jobs.

The experiment list sits at the top and feeds everything below it: tune one, run them all, aggregate their results. The pipeline rail is the same surface in every mode — batch just walks it automatically.

01

Experiments at the top

The folder picker is the shared substrate. Each experiment shows its own mini-rail — which stages are done, running, pending — so you read the whole series at a glance.

02

Active stages only

Each stage has an on/off toggle. Turn Stress off (no MSM — common) and it reads as off, never missing; status only judges the stages you've enabled.

03

Run all walks the rail, live

Batch isn't a separate screen. "Run all" steps every experiment through the active stages and streams previews into napari as it goes.
